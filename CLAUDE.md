# Reference Sheets

Markdown-driven reference dashboards (energy, robotics and manufacturing, defense and aerospace) rendered as searchable, filterable static sites from a shared engine.

- **Live site**: https://humbaventures.com/reference/ — GitHub Pages, redeploys automatically on every push to `main` (repo is `lpolovets/reference`; Pages mounts at `/reference/`). Each sheet builds into its own subdirectory (`/reference/manufacturing-processes/`, `/reference/battery-chemistries/`); the root is a landing page indexing all sheets.
- **claude.ai artifact**: a copy of the manufacturing sheet at https://claude.ai/code/artifact/af9b8583-110f-42ce-b2dc-29326b27b24d. It never updates automatically — rebuild with `--artifact manufacturing-processes` and republish `dist/manufacturing-processes.artifact.html` via the Artifact tool (pass this URL as `url` from a session that didn't originally publish it).

## Writing style (important)

All prose (entry sections, guide.html, h2h.html, blurbs, ledes) must follow **STYLE.md** — Leo's plain, engineer-explaining-to-a-friend voice, not default AI style. Read STYLE.md before writing or editing any prose. Quick version: plain declarative sentences, concrete numbers, if/then advice, honest hedging ("usually", "roughly"); no aphoristic em-dash flourishes, dramatic vocabulary, or "not X — but Y" constructions.

**`node build/style.js` checks prose against STYLE.md's "Don't" list** and runs in CI on every push (`.github/workflows/style.yml`). It covers entry sections, guide/h2h text and the `sheet.json` strings, and skips `## Further reading` and `## Videos`, whose titles are the publisher's words. Every rule is high precision and the corpus currently scores zero — that was the design constraint, because a linter that fires on prose which is fine gets muted and then protects nothing. Rules tried and dropped for that reason are recorded at the top of the file: em dashes per paragraph (203 paragraphs use a legitimate matched pair, and the worst "offenders" were table rows that only look like paragraphs once tags are stripped), bare "not just X" (16 uses, all ordinary contrast), and the words "seismic" and "unlock" (real technical vocabulary here). The aphorism rules require a negation or a copula after the dash, which is what separates `the constraint is not geology at all — it is which refineries bother` from `There is no remote attack on an inertial unit — it senses only its own motion`. **If a rule ever fires on prose that reads fine, fix the rule, not the sentence.**

## Workflow rule (important)

**Review-then-push.** Make changes locally, demonstrate them (screenshot or local preview), and only commit/push/republish after Leo explicitly approves. A request to change something is not approval to publish it. One approval covers one push.

## Layout

- `sheets/<slug>/` — one directory per reference sheet:
  - `sheet.json` — all sheet config: titles, lede, unit words, group label, the seven parts/classes (each part takes an optional `blurb` — a short lowercase purpose phrase, under ~55 chars, shown on its explorer tile; avoid raw `&`, it's injected unescaped), and **facet definitions** (`id`, frontmatter `key`, `label`, `type` multi|range|single, `color` var, `options`, `order`, optional `chipLabels`/`tagPrefix`/`tip`/`required`/`tagRow`), plus `extraSections` mapping optional markdown sections to card labels.
  - `entries/NNN-slug.md` — one file per entry. Frontmatter: `number`, `name`, `part`, `group`, plus one key per facet (keys validated against sheet.json). Sections: `## Description`, `## Strengths and weaknesses`, `## When to use` (prescriptive: when to pick it, when to avoid it, and the usual alternative; present on all entries since 2026-07-25), then optional `## Variants` (with `###` entries), `## Videos`, and the sheet's remaining extra sections (`## Examples`, `## Economic profile`).
  - `guide.html` — the sheet's guide-tab content (raw HTML fragment using shared classes: `.tblwrap`, `.bands`, `.callout`, `.qlist`). Ends with a **Glossary**: a `.tblwrap` table of 12–18 alphabetical terms drawn from the sheet's own entries, each defined in 1–3 plain sentences.
  - `h2h.html` — the "Head-to-head" tab. Opens with one comparison table of the 5–8 high-level options that actually compete, then **2–3 further tables covering the sub-decisions within a class** (a single top-level table is too coarse on its own). Every table ends with a "Pick it when" column (last `<td>` renders muted; first `<td>` is bold/nowrap so keep row names short) and carries real numbers in the middle columns. Optional file: if absent the tab is omitted (tab label via `h2hTab` in sheet.json, default "Head-to-head"). Uses the same shared classes as guide.html — the view reuses `class="guide"` styling.
  - `images/NNN.jpg` (optional) — per-entry illustration keyed by zero-padded entry number (.jpg/.png/.webp); rendered at the top of the card body on the website flavor only (the artifact blocks external requests).
  - `images/prompts.json` (optional) — the generation prompts for that sheet's illustrations, so the set is reproducible: `{"anchor": <entry number>, "style": "<optional override>", "prompts": {"1": "...", ...}}`. Consumed by `build/generate-images.js`; the build copies only image files out of `images/`, never this.
- `shared/` — everything common: `theme.css` (all styling, inlined into every page at build), `page.html` (skeleton with `{{...}}` placeholders), `app.js` (the generic explorer engine, driven by an injected `SHEET` config), `logo.html`.
- `build/build.js` — plain-Node build; auto-discovers `sheets/*/sheet.json`.
- `.github/workflows/pages.yml` — build + deploy on push.

## Build

```bash
node build/build.js                       # -> site/<slug>/ per sheet (page + data.json) + site/index.html landing
node build/build.js --artifact <slug>     # -> dist/<slug>.artifact.html (fragment for the claude.ai artifact)
node build/build.js --check               # validate every sheet, write nothing
node build/build.js --allow-incomplete    # build, skipping sheets that have no entries yet
```

No dependencies. The build validates frontmatter and video lines and fails naming the offending file. `--check` runs exactly those validations and writes nothing, which is what to use when several agents are editing entries in parallel (a full build would have them racing on `site/`). It isolates each sheet, printing `ok` / `pending` / `FAIL` per slug and exiting non-zero only if something actually failed, so one agent's broken file doesn't mask everyone else's status.

**A sheet still being written doesn't fail the run.** With no entry files at all it reports `pending`; with some of its groups still empty it reports `partial` and lists them. Both skip the `groupBlurbs` cross-check, which would otherwise fail against a half-populated group set and take every other sheet's status down with it. A real build refuses to ship either state, since the result would publish as an empty or holed page; pass `--allow-incomplete` to drop those sheets from the build and preview everything else. The landing page and the about page count only the sheets that actually built. Verify UI changes by serving `site/` locally (there's a `.claude/launch.json` "site" config on port 8741) and loading `/<slug>/` (add a throwaway `?v=` query when re-testing — the preview browser caches hard).

## Conventions and gotchas

- **Adding a sheet**: create `sheets/<slug>/{sheet.json,guide.html,entries/}`; the build and landing page pick it up automatically. Reuse `--p1..--p7` for part colors and `--fa..--fe` for facet colors (blue/gold/red/green/purple — all defined once in `shared/theme.css` for both themes; add a new var there if a sheet needs a sixth facet).
- **Facet types**: `multi` = array field, one tag per value; `range` = ordered array collapsed to a "Prefix: First–Last" tag (labels must be single words or the dash collapse reads badly); `single` = scalar, `none`/omitted allowed unless `required` (no tag rendered when absent, and entries without it match only when that facet filter is empty).
- **`tagRow: 2`** on a facet puts its card tags on their own second line under the others, right-aligned to match (battery-chemistries uses it for applications). Facets without it share the first row with the expand caret.
- **Shared style**: all styling lives in `shared/theme.css` and is inlined into every page at build — edit it once and every sheet (and the landing page) changes together. Keep the label column (`.facet .flabel`, 108px) wide enough for the longest facet label across all sheets; long labels wrap badly otherwise.
- **Further reading**: 1–2 links per entry in a `## Further reading` section (last extra section), one line, links `[Title (Publisher)](url)` separated by " · ". Policy: canonical sources only — institutional reports, trade-association primers, vendor *educational* content, open-access reviews; one practical + one deep link where both exist; **every URL must be fetch-verified live before inclusion**; skip the section rather than pad (deliberately empty as of 2026-08-09: manufacturing 025 slush casting only — the other three long-standing gaps were filled that day from NPTEL lecture PDFs, an EPA AP-42 section, American Machinist, IIBEC, and The Fabricator; slush casting still has no canonical source, only anonymous reference sites, a paywalled ASTM ingot spec, and a `vlabs.ac.in` page whose TLS certificate has expired). Known bot-blockers that still work in browsers: ASM Digital Library, Edmund Optics, COBOD, Panasonic PDFs, **The Fabricator** (Cloudflare interstitial to every fetcher; verify its articles by loading them in the browser pane), **`pubs.usgs.gov`** (403s WebFetch, 200s to a browser user agent — `curl` with a browser UA plus `pdftotext` works), **`gao.gov`** (403s with a 399-byte body even to a browser UA in curl, on both `/products/` pages and `/assets/*.pdf`, but WebFetch reads the product pages fine and the browser pane works too — a curl-only check wrongly rejects it, and GAO product numbers are exactly the kind of identifier that gets invented, so verify every one), **`nickelinstitute.org`**, **`intlmag.org`**, **`tms.org`**, and **`icao.int`** (its HTML pages verify via WebFetch even though curl is refused). Sites that block fetchers entirely (avoid): ScienceDirect, Wiley, MDPI direct (use PMC mirrors), ACS, RSC, NRC, IAEA PDFs, SemiEngineering, NDE-Ed.org, automate.org, Festo, **`semi.org`**, **`pubs.aip.org`** (AVS/AIP — use IOPscience or PMC for the same papers), **IEEE Spectrum** (serves account prompts with partial content, so a fetch looks like it worked), `crsreports.congress.gov`, `sto.nato.int`, `dosits.org`, `analog.com`, `defence.gov.au`, and most `.mil` hosts (`af.mil`, `army.mil`, `navair.navy.mil`, `navsea.navy.mil`, `defense.gov`). Two other traps: **`inst.eecs.berkeley.edu`** now redirects its course PDFs to a CAS login, and **`scis.scichina.com` is HTTP-only** — port 443 times out, and WebFetch upgrades to HTTPS, so it can never be verified that way. **PMC** serves a CAPTCHA shell to fetchers; get titles from the NCBI E-utilities API instead.

**Verifying a PDF needs `pdftotext`, not WebFetch.** WebFetch hands the model raw binary for a PDF and it will confabulate a plausible title from the URL. Download it and read the actual title page. Two examples of the sharpest failure mode, where a URL returns a real document that is **the wrong document**: `database.ich.org/sites/default/files/Q6B_Guideline.pdf` serves Good Clinical Practice instead of Q6B (the real one is `Q6B%20Guideline.pdf`, with a space not an underscore), and an `oecd-nea.org/jcms/pl_51110/unlocking-reductions-in-the-construction-costs-of-nuclear...` slug serves *Projected Costs of Generating Electricity, 2020 Edition*. A status code, a content-type, and a plausible file size all pass while the content is something else. Only reading the cover catches it. The clearest demonstration: a *guessed* USGS fact-sheet number, `pubs.usgs.gov/fs/2024/3033/fs20243033.pdf`, downloads a clean valid PDF — about invasive blue catfish in Chesapeake Bay, not the geologic-hydrogen report the guesser wanted. Guessing a document number will often land on a real document. When extracting, take the **first two pages**: OSTI-hosted NETL reports put boilerplate disclaimer on page 1 and the real title page on page 2.

**NREL is now the National Laboratory of the Rockies (NLR), at `nlr.gov`.** `nrel.gov`, `www.nrel.gov`, and `docs.nrel.gov` have **no DNS record at all** — verified 2026-08-09 — so every `nrel.gov` URL is dead and an agent citing NREL from memory will produce an unreachable link. Use `www.nlr.gov` and `docs.nlr.gov` (the hosted PDFs are still NREL-branded, so name the publisher as it appears on the document you are linking to). DOE reorganized alongside it: `energy.gov/eere/...` and `energy.gov/fecm/...` now redirect to `energy.gov/cmei/...` and `energy.gov/hgeo/...`, and the ATB moved to `atb.nlr.gov`. **`liftoff.energy.gov` is gone entirely** (DNS failure), so the DOE Pathways to Commercial Liftoff reports can no longer be cited there. Also fully blocked: **JEDEC** (`jedec.org`, Cloudflare 403 to everything, so its standards cannot be cited), `emp.lbl.gov` (bot check to curl *and* the browser pane — cite Berkeley Lab work through the DOE or OSTI mirror), `unido.org`, `epj-pv.org`, `ember-energy.org`, `turbomachinerymag.com`, `aerospace.org` (its Center for Space Policy and Strategy papers cannot be verified at all), `satelliteconfers.org`, the `netl.doe.gov/carbon-management/turbines/handbook` index (its chapter PDFs under `/sites/default/files/` are fine), and `irena.org` / `iea.org` / `esmap.org` landing pages — though those last three serve their PDFs fine from `iea.blob.core.windows.net`, `-/media/`, and `documents1.worldbank.org`, so cite the PDF. The same split holds for **`netl.doe.gov`** (HTML 403s even with a browser UA, PDFs under `/projects/files/` serve fine, so Gasifipedia is uncitable) and **`theicct.org`** (landing pages Cloudflare-blocked, `wp-content` PDFs fine). `carbontrust.com` report pages are lead-capture gated but the underlying `sites/default/files/` PDFs are not. `utahforge.com` has an incomplete TLS chain, which curl tolerates and WebFetch rejects. **`www.pnnl.gov` 403s a HEAD request but serves GET normally**, so a status-code-only check wrongly rejects it.

**More client-rendered shells that 200 on anything** (same trap as `ntrs.nasa.gov/citations/`): `openknowledge.fao.org` item pages are 945-byte shells — verify through its DSpace API (`/server/api/pid/find?id=hdl:...`). And `tools.thermofisher.com` serves a 435-byte HTML error page with `content-type: application/pdf`.

**Blocks that need a browser user agent rather than WebFetch:** FDA guidance pages (`fda.gov/.../inspection-guides/...` returns 404 to WebFetch, 200 to a browser UA), and Cytiva on both `www.` and `cdn.` hosts (403 with an 846 KB HTML body, large enough to look like a real download — university mirrors of its handbooks work). `sigmaaldrich.com` refuses the connection outright, `merckmillipore.com` 403s, and `uspnf.com` 403s every fetcher.
- **Verifying a link is not the same as verifying a status code.** Two traps found on 2026-07-26 while building the defense sheets:
  - `ntrs.nasa.gov/citations/<id>` returns HTTP 200 for *any* id, because the page is a client-rendered shell. Check the id against the JSON API instead: `curl https://ntrs.nasa.gov/api/citations/<id>` returns `{"statusCode":404}` for a bad id and a document with a `title` for a good one. Find real citations with `https://ntrs.nasa.gov/api/citations/search?q=<terms>&size=5` and copy the returned title verbatim.
  - `apps.dtic.mil` has been serving an "Under Maintenance" page, so DTIC accession numbers cannot be verified at all right now. Don't cite DTIC until it is back.
  - **`gps.gov` restructured its URLs.** The long-standing `/systems/gps/`, `/systems/gps/space/`, and `/systems/gps/control/` paths now 404 (loudly, with a real "Page not found" body). Content moved to flat slugs: `/gps`, `/gps-space`, `/augmentation-systems`, `/technical-documentation`, `/performance-standards-specifications`. Anything citing gps.gov from memory produces a dead link. Note `/gps-space` covers *using* GPS in space (the space service volume), not the GPS space segment — an easy mislabel. **`artes.esa.int` has no DNS record at all**; `www.esa.int` and `connectivity.esa.int` carry the same ARTES material.
  - `ntrs.nasa.gov/api/citations/search` is the right tool for NASA's own historical work but the wrong one for anything post-2015 and commercial — searches for orbital transfer vehicles or space tugs return shuttle-era studies. And `ccsds.org/Pubs/<doc>.pdf`, the short path most references cite, is a plain 404; the real files sit under a long `wp-content/uploads/gravity_forms/...` path that has to be scraped from the publications index rather than constructed.
  - Titles matter as much as URLs. After fixing URLs, fetch each page's `<title>` and make sure the link text matches what the page actually is — a generic index page must be labelled as one ("Research publications (RUSI)"), not as a specific paper.
- **CRS reports**: cite them through `https://www.everycrsreport.com/reports/<NUM>.html`, which is fetchable and carries the report title in `<title>`. `crsreports.congress.gov` returns 403 to every fetcher, so a link there can never be verified — and report numbers are easy to guess wrong (several plausible-looking `IF#####` numbers turned out to be reports about unrelated subjects).
- **Key numbers**: every entry carries a `## Key numbers` section right after `## When to use` — one line, 4–7 quantities separated by ` · `, no prose sentences. It should restate the numbers already in the entry's other sections rather than introduce new claims, so it never contradicts them. Which quantities suit which sheet is a per-sheet decision (tolerance/finish/lot size/tooling cost for manufacturing; Wh/kg, cycle life, $/kWh for batteries; endurance/range/payload/unit cost for uncrewed systems).
- **Derived conclusions: show the chain or mark it.** Some of the sharpest claims in these sheets are arithmetic nobody publishes — the price at which refuelling beats a life-extension pod, the delivered $/MWh of hydrogen power, the cost per gram of antibody off a Protein A column. Those are legitimate and often the reason an entry is worth reading, but a reader must never mistake one for a looked-up figure. Two acceptable forms: **show every step** so the arithmetic is visible (hydrogen 031 does this — 33.3 kWh/kg, 20 kWh back at 60%, so 50 kg/MWh, so $200–300/MWh at $4–6/kg), or **state plainly that it is derived** when the conclusion is given without the steps (space-launch 031 says "derived here, not published"). What is not acceptable is a computed conclusion sitting in Key numbers looking exactly like the sourced quantities beside it.
- **Videos**: max 3 per entry, format `- <YouTube watch URL> — Title (Channel, N minutes, band+ views)`. Policy: embeddable, playable, not live, ~1.5–20 min (≥1 min for popular animations), prefer popular/maker-community explainers; leave the section out if nothing good exists. View bands: 1k/5k/10k/50k/100k/500k/1m/5m, or "under 1k views".
- **The video line is split into fields at build time** by `splitVideoMeta` in build.js, giving `{id, t, c, dur, vw}` rather than one string: runtime renders as a badge on the thumbnail, channel and views as a caption under the title. The markdown format is unchanged, so `yt.js audit` — which reads the entry files, not `data.json` — is unaffected. **Do not match the trailing parenthetical with a regex on `" ("`.** Titles and channel names both contain parentheses (`JoVE (Journal of Visualized Experiments)`, `Sumitomo (SHI) Demag`, `Tesla 4680 Teardown (Part 2)`), and the ambiguity cuts both ways: a greedy match splits the Sumitomo case wrong, a lazy one splits the Part 2 case wrong. Scan backwards from the end for the balanced group that closes the line, which is unambiguous — that parses all 2,061 lines, where the obvious regex leaves 21. A line with nothing to split off keeps its title and simply renders without a caption.
- **Duration badges use fixed dark chrome**, not theme variables: they sit on the thumbnail image and have to stay legible over whatever the frame happens to be, in either theme. In the artifact flavor there are no thumbnails, so duration joins the caption and each video takes its own line — joined by `<br>` rather than a middot, because the captions are themselves middot-joined and running them together reads as one string.
- **Fetching YouTube metadata**: use `build/yt.js`, never a hand-written line.
  ```bash
  node build/yt.js search "how a molten salt reactor works" --n 12   # candidates, duration-filtered
  node build/yt.js line 6v35VrNMfaU                                  # verified markdown line, or REJECT
  ```
  `line` re-reads the title, channel, duration, and view count from YouTube and prints the exact line to paste, so a hallucinated or mistyped id fails loudly. It appends `# check length` when a video sits outside the comfortable duration band — decide, then delete the comment.
- **Monthly link rot check**: `.github/workflows/linkcheck.yml` runs `build/links.js` (further reading) and `yt.js audit` (videos) on the 1st of each month, and files or updates one issue per month when either finds rot. Both are runnable by hand: `node build/links.js [sheet-slug]`.
  - **The design problem is false positives, not fetching.** Most of the good sources here refuse automated clients, so a naive checker reports dozens of dead links a month and gets ignored by the second month. Results are graded instead: **DEAD** (404, 410, host does not resolve) fails the run; **SUSPECT** (200 but the shape lies) and **BLOCKED** (403/429, challenge page, known blocker) are listed and do not. A refusal is not a missing page, and that matters more from a CI runner than a laptop, because datacenter IPs get walled far more aggressively.
  - Anything grading DEAD or SUSPECT is **re-checked once after a pause** before being reported, because rate limits are transient and real rot is not. Without it, hitting the same hosts twice in an hour produces a page of false alarms — SiteGround answers 202 with a meta refresh to `/.well-known/sgcaptcha/`, which is a wall, not a dead link.
  - Distinctions worth keeping: `content-type: application/pdf` with a non-PDF body is a **lying server** (the Thermo/Cytiva trap, SUSPECT); a `.pdf` URL answered with `text/html` means a **bot wall handed us a page instead of the file** (BLOCKED — `docs.nlr.gov` does this to Node while serving curl the real 2 MB PDF). And a TLS error is not a dead host: NASA and `.mil` hosts chain to roots Node does not carry but browsers and curl do, so `UNABLE_TO_VERIFY_LEAF_SIGNATURE` is reported as its own thing rather than "no response".
  - Hosts needing their API instead of their page are handled directly: PMC through E-utilities (comma-joined ids, so 137 links cost two requests), NTRS through `/api/citations/`, `openknowledge.fao.org` through its DSpace `pid/find` endpoint. Redirect targets are graded too, since many links are DOIs that land somewhere else.
  - `yt.js audit` grades the same way: oEmbed 400/401/403/404 means gone or embedding-off, but a 429, a 5xx or a socket error is **UNCHECKED**, listed and not failed. It used to treat every error as GONE, which from a CI IP would have filed an issue claiming every video died at once.
  - In the workflow, `set -o pipefail` in the check steps is load-bearing: the default shell is `bash -e` with pipefail off, so `node … | tee` would report tee's status and every month would look clean regardless.
- **Video link rot**: `node build/yt.js audit [sheet-slug]` re-checks every video already stored in the entries and reports `GONE` (deleted, private, or embedding switched off) and `RETITLED` (the stored title no longer matches the live one). Exits non-zero when anything is gone, so the monthly link-rot routine can run it alongside the further-reading check.
- **The YouTube endpoints each answer half the question.** Watch pages captcha-block curl. The innertube `search` endpoint works fine. The `player` endpoint now returns `playabilityStatus: UNPLAYABLE` for *every* anonymous caller because the streaming URLs are bot-gated, so **its status field is useless** — but the `videoDetails` it returns (duration, view count, live flag) are still correct. Availability and embeddability come from oEmbed instead, which 400s on a dead, private, or embed-disabled id. `yt.js` combines the two; if YouTube tightens further, that function is the thing to fix.
- **Illustration lightbox**: clicking a card illustration opens it full size. The image is wrapped in an `<a>` pointing at the image file rather than a button, so the click works without JS (it just shows the file) and the image becomes keyboard-reachable; app.js intercepts the click and shows the overlay instead. Esc, the backdrop, and the close button all dismiss it, and focus returns to the link. The lightbox sits at `z-index:70`, above the shortcuts panel, and is checked first in the Esc chain; while it is open the `/`, `?` and `j`/`k` shortcuts are swallowed, since they would act on a list the reader cannot see. Note that a `.cimglink` inside a collapsed card is inside `display:none` and cannot take focus — that is expected, and it makes any focus test written against a closed card silently meaningless.
- **Illustrations**: `build/generate-images.js` is sheet-driven off `sheets/<slug>/images/prompts.json`.
  ```bash
  node build/generate-images.js anchor nuclear-reactors    # the style-anchor image
  node build/generate-images.js batch nuclear-reactors 2   # 2 candidates per entry, conditioned on the anchor
  node build/generate-images.js edit <png> "<instruction>"  # cheap targeted iteration
  ```
  Output goes to a scratch dir (printed on start, override with `$IMG_OUT`), never straight into the repo — **every image gets human eyes before it is copied to `sheets/<slug>/images/NNN.jpg`**. The Gemini key is read from `../.gemini_api_key`, one level ABOVE the repo root; never commit it. All sheets share one house style so the illustrations look like a set; a sheet can override it via `"style"` in its prompts.json. Image-edit mode is much cheaper than regenerating. Prompt-writing lesson from robot-end-effectors: name the one piece of geometry that identifies the subject, and for anything gripping or holding, ask explicitly for a side view with the object clearly lifted, or the model draws it resting on a surface.
- **Artifact flavor must stay pure ASCII** (the artifact host serves no charset header); the build escapes this automatically. The artifact also blocks all external requests — video embeds degrade to links there (`EMBED_OK` flag).
- **Theme**: site defaults to dark via a pre-paint inline script + localStorage; the Light/Dark chip is website-only (the artifact viewer has its own theme control).
- **CSS trap**: `nav.tabs button` styles bleed into any button added to the tab bar — exclude additions via `:not()`.
- **CSS trap**: `.facet .flabel` is `white-space:nowrap`, and the tooltip lives inside it, so `.tipbody` has to reset `white-space` along with `text-transform`, `letter-spacing` and `font-weight`. It didn't until 2026-08-10, which meant every facet tooltip rendered as one long unwrapped line spilling out of its 280px box and across the rows underneath — a 582-character tip drew a 71px-tall box. Reset all four when adding anything else inside a label. The tooltips also carry `--surface2`, not `--surface`, because `--surface` is the filter panel's own background and an overlay the same colour as what it covers reads as broken. Tips run to 300px+, so app.js measures on hover and adds `.up` to open the box above the label when it would otherwise run off the bottom of the screen.
- **Anchors**: each card's `id` is its name slugified (same slug as its filename); `#slug` deep links open and scroll to the card. Renaming an entry changes its slug and breaks old links.
- Header stats (entry/part/group counts) and the copyright year are computed at build time.
- **Landing page**: sheets group under `category` headings from sheet.json. The running order is the explicit `CATEGORIES` list in build.js — Energy, Robotics and Manufacturing, Materials, Defense and Aerospace, Bioprocessing — and anything not listed falls in after those in order of first appearance. It used to be first-appearance for everything, which meant adding a sheet could silently reshuffle the page. **Add a new category to that list when you add a sheet that introduces one.** Cards show `question` (italic accent line), `blurb`, and entry count.
- **About page**: `shared/about.html` is the methodology page, rendered to `site/about/index.html` and linked from the landing footer. It uses `{{N_SHEETS}}`, `{{N_ENTRIES}}`, `{{N_VIDEOS}}`, and `{{YEAR}}` placeholders, all computed at build time so the prose can't go stale as sheets are added. A global search box (shared/landing.js, inlined at build) lazily fetches every sheet's `data.json` on first focus and searches names/groups/parts/card text across all sheets, linking to `<slug>/#<anchor>`.
- **Filter-state URLs**: the explorer mirrors its state into the query string (`p` = part ids, one param per facet id with comma-joined option keys, `q` = search, `sort` = sort id, `dir=desc`) via history.replaceState, and restores it on load — filtered views are shareable links. "Reset filters" clears filters but deliberately keeps the sort.
- **Sorting**: the sort dropdown offers Catalog order, Name, and every ordered non-multi facet (auto-derived per sheet); an asc/desc toggle appears when sorting. Sorted views render flat (no group headers); entries lacking the facet always sort last. Range facets sort by their highest band.
- **How options inside one facet combine** is decided by the facet's *type*, because the data decides it — see `matchesExcept` and `narrows()` in app.js. A `multi` facet is a set of independent tags an entry can carry several of, so picking two means "carries both" and **each pick narrows** (semiconductor Device: Logic + Memory = 18 of 32). A `single` facet holds one scalar and a `range` facet holds one span, so there picking two can only mean "either", and each pick widens. **AND is not available on `single` facets and never will be**: across all 18 sheets, 408 of 408 two-chip pairs on single facets contain zero entries, because no entry has two tool costs or two supplier counts. Range facets can AND (47 of 103 pairs are non-empty) but the union is the natural read of a span. Each facet's tooltip states its own rule, generated from the type by `COMBINE_NOTE` in build.js, so no sheet has to remember to say it.
- **Facet chip counts**: every chip carries the number of entries it would leave visible, and dims at zero. The base set depends on which way the facet combines. A **narrowing** facet keeps its own selection applied (`matchesExcept(x, null)`), so each chip's number is literally "click me and you will have N left" — verified across 5,040 filter states, not just simple ones. A **widening** facet must drop its own selection (`matchesExcept(x, facet.id)`), or picking one band would read every unselected sibling as zero when each would in fact add entries back; there the number is what the band contributes, and it equals the result count only when it is the sole pick in its facet. Recomputed on each render, one pass over the entries per facet. The count sits in a `.fn` span marked `aria-hidden`, with the chip's `aria-label` rewritten to "Label, N matching" so it isn't lost to a screen reader; the plain label is stashed on the element as `_label` when the chips are built, because the chip's own markup has already been through `innerHTML`.
- **Sticky results bar** (`#resBar`): a floating "N / 212 · Reset · Top" pill that appears once `.filters` has scrolled off the top. It lives *inside* `#view-explorer`, so `.explorer{display:none}` hides it on the guide and h2h tabs with no extra state; `updBar()` still checks the active class so `aria-hidden` stays honest. Hidden with `visibility`, not `display`, so it drops out of the tab order and can still animate. Reset is hidden unless something is actually filtered (`filtered()`, which deliberately ignores sort, matching "Reset filters").
- **Keyboard shortcuts**: `/` focuses search, Esc clears it then blurs, `j`/`k` step between card headers, `?` opens the help panel. The card headers are already `<button>`s, so Tab, Enter and Space work natively — **do not add an Enter handler**, it would fire alongside the native activation and toggle twice. The arrow keys only move the cursor when a header already holds focus, so they keep scrolling the page the rest of the time. Discoverability is one `/` badge inside the search box, shown only under `(hover:hover) and (pointer:fine)` since it is noise on a phone. That badge is why `.search` is a `<div>` and not a `<label>`: a label swallows clicks on any interactive child, and a button inside one is invalid anyway. The landing page's own `.search` is still a label — it has no badge.
- **Group blurbs**: sheet.json `groupBlurbs` maps every group name to a short purpose phrase shown in the list group headers (hidden on mobile); the build fails if the map and the entries' group names don't match exactly. Class-level `blurb`s appear on the part tiles only.
- **Prerendered cards**: `shared/render.js` holds the only copy of the entry-card markup. build.js `require`s it to fill `{{LIST}}` in page.html, and injects the same file into the page ahead of app.js, so the HTML that ships and anything a filter redraws come from one implementation — a second copy in build.js would drift and show up as a flash of different content on load. It is a factory (`makeRenderer(SHEET, EMBED_OK)`) because both callers need those two ambient values, and the build passes the same `clientSheet` object the page gets. **Verify a change to it by diffing shipped against redrawn**: set a detached div's innerHTML to `R.listHTML(P, true)` and compare with `#list.innerHTML`, so both go through the same parser — comparing the raw string against `innerHTML` reports false differences, since the browser rewrites `<path/>` to `<path></path>`.
  - The client is told whether it got prerendered markup via `PRERENDERED`, and skips the first `innerHTML` write when the initial state matches what shipped (catalog order, nothing filtered). A URL carrying filters or a sort re-renders normally. **The artifact flavor is deliberately not prerendered** — it always runs JS, nothing crawls it, and the entries are already in the page as JSON, so prerendering would double the file for no reader who benefits. That is why the flag exists: a page built without prerendering must render on load or the list stays empty.
  - Cost: the entries ship twice, once as HTML and once as the `P` JSON the client needs for search and filtering, which is +50–90% on the wire after gzip (manufacturing 190K → 357K). First paint is still earlier, because the browser draws streaming HTML instead of waiting on JS. The duplication is removable — filter by hiding prerendered cards instead of rebuilding them, and take the search haystack from each card's `textContent` — but that is a rewrite of render/filter/sort, not a tweak.
  - `<noscript>` in page.html opens every card body and hides the controls that cannot work, so a reader without JS gets all 750 entries as a plain document.
- **Placeholder substitution goes through function replacers.** `String.prototype.replace` rewrites `$$`, `$&`, `` $` `` and `$'` in the replacement even when the search pattern is a plain string, so `"Costs $$"` in a guide or an entry would silently corrupt the page (`$&` expands to the placeholder itself, `` $` `` to everything before it). Every `.replace('{{X}}', …)` in composeBody passes `() => value` instead, which is exempt. Nothing in the repo trips it today; `{{LIST}}` alone injects ~900KB of authored prose, so keep new injections in the same form.
- **Head tags and social unfurls**: `head()` in build.js emits the whole document head for all three page kinds (sheet, landing, about) — title, meta description, canonical, OpenGraph, Twitter card, and the icon links. It takes `path` (the page's location under `SITE`, `''` for the landing page) and `up` (the prefix back to the site root, `../` for sheet and about pages), because Pages serves everything from `/reference/` and a root-absolute `/favicon.ico` would 404. Sheet descriptions come from `sheet.blurb`; the landing description appends the entry, sheet, and category counts at build time so it cannot go stale. Attribute values go through `escAttr`, not `esc` — `esc` leaves quotes alone, which is fine for text nodes and not for `content="…"`. The artifact flavor has no head at all (the Artifact tool supplies one), so none of this touches it.
- **No `og:image`.** A card worth having would print the sheet's title, that needs font rasterization, and nothing in this dependency-free repo can do it. One generic banner on all 18 sheets unfurls worse than a clean title-and-description card. If it ever gets added, the images have to be real PNG/JPEG — every major unfurler ignores SVG for `og:image`.
- **Favicons are generated, not committed**: `build/icons.js` writes `favicon.svg`, `favicon.ico` (16/32/48) and `apple-touch-icon.png` (180) into `site/`, which is gitignored, so CI regenerates them on every deploy. It hand-rolls a PNG encoder over Node's built-in `zlib` and packs the ICO directory itself rather than taking a dependency; shapes are pure geometry (a rounded tile plus three bars) so no font is involved. `inRound()` is shared by the rasterizer and the SVG writer so the two flavors can't drift. The `<link>` for the .ico deliberately declares only `sizes="32x32"` even though it holds three: an unqualified .ico outranks the SVG in Chrome, and the SVG is the one that stays sharp on a high-DPI tab.
- **Logo link**: the Humba logo links to the reference-sheets landing page, not humbaventures.com. `shared/logo.html` carries `{{HOME_HREF}}`/`{{HOME_EXTRA}}` placeholders filled per flavor by `logoFor()` in build.js: sheet pages `../`, landing `./`, artifact absolute URL with `target="_blank"`.
